数据库内核

数据库概述

四大特性（ACID）
A：原子性
C：一致性
I：隔离性
D：持久性

1.数据库主要功能

数据定义功能

  • 提供数据定义语言(data definitionlanguage，DDL)
  • 定义数据库中的数据对象(创建、删除、修改表/索引/视图)

数据操纵功能

  • 提供数据操纵语言(data manipulationlanguage，DML)
  • 实现对数据库的基本操作(查询、插入、删除和修改数据)

数据组织、存储、查询处理

  • 分类组织、存储和管理各种数据，确定组织数据的文件结构和存取方式
  • 数据库高效查询和执行
  • 数据库事务管理、故障恢复、备份恢复、安全处理

2.不同层的分工

查询处理层：

  • 查询解析、查询重写
  • 查询优化(基数、代价估计、计划选择)

查询执行层

  • 形成数据库语言语句的执行计划。
  • 执行模型、执行算子

存储管理层

  • 在数据存储器中完成数据的增删改查操作
  • 数据组织、缓冲区管理、索引
  • 事务处理、并发控制、故障恢复

安全管理

  • 负责数据库全生命周期的安全管理

01-关系模型

1.关系模型

  • 用简单数据结构存数据
  • 用高级语言访问数据
  • 大型数据库的物理存储策略基于 Database Management System 的实现

这种思想把 逻辑层 和 物理层 完全解耦

关系模型主要关注三个部分：

  • 结构：关系及其关系的定义内容。
  • 完整性：确保数据库的内容满足要求约束条件。
  • 操作：如何访问和修改数据库的内容

一些定义：

  • 主键 Primary Key，唯一标识记录的 id

  • 外键 Foreign Key，用于指定一张表中的属性必须存在于另一张表中

DDL：创建数据库语言
DML：修改数据库语言

03-数据库存储

DBMS（Database Management System）：数据库管理系统
DBMS主要组成部分：

  • 1.存储管理器：

    • 管理数据的物理存储，包括数据在磁盘上的分布。
    • 支持分页、区段、缓存管理。

  • 2.查询处理器（Query Processor）
    解析、优化和执行 SQL 查询。
    包括：

    • 解析器（Parser）：将 SQL 语句转换为查询树。
    • 查询优化器（Optimizer）：生成最优的查询执行计划。
    • 执行引擎（Execution Engine）：执行查询计划。

  • 3.事务管理器（Transaction Manager）
    管理事务的执行，确保事务的原子性、一致性、隔离性和持久性（ACID）。

  • 4.并发控制管理器（Concurrency Control Manager）
    管理多个用户的并发访问，避免数据冲突。
    采用锁、快照隔离、MVCC（多版本并发控制）等机制。

  • 5.日志与恢复管理器（Log and Recovery Manager）
    记录操作日志（如 redo log 和 undo log），用于事务的回滚和崩溃恢复。

DBMS基本操作流程：
1.用户发起 SQL 请求：

  • 用户通过客户端发送 SQL 语句。

2.查询解析与优化：

  • 查询处理器将 SQL 转换为查询树。
  • 优化器生成最优的执行计划。

3.数据检索或修改

  • 存储管理器在磁盘或缓存中查找数据。
  • 对数据进行读取或写入操作。

4.事务处理

  • 如果是事务，DBMS 会记录操作日志，并在事务提交后更新数据。

5.返回结果：

  • 查询结果通过网络返回给用户。

4.日志结构的文件组织

主要是存储如何创建 tuple 以及修改 tuple 的相关信息，比如增删改查的操作

这些记录会以文本文件的形式保存，读起来就像是日志记录一样。

为什么要这么做？
循序写入/读取/访问的速度要远比随机访问快得多。如果使用 Slotted Pages 的方式，假设要更新 10 个在不同 page 上的 tuple，那就必须在这 10 个 page 上来写入并更新这些 tuple。但如果使用的是 Log-Structured 文件组织这种形式，把这要更新的 10 个 tuple 的语句写在单个 page 上，就一次性能搞定全部了。

这种做法的问题：如果想要去读取某一个tuple，就需要在日志中查找这个tuple。
